## 背景・位置づけ

本体（ニュース起因シグナル）は「TDnet開示/ニュース → 寄り前に候補を絞る」道具で、**材料を伴わない
テーマ・需給・テクニカル駆動の動意は構造的に対象外**（柱2破棄の方針）。
2026-06-23の調査では、値上がり率トップ24のうち**17件が適時開示なし＝テクニカル/需給駆動**だった。

これらを取りこぼしたままにせず、**別系統の「テクニカル版 朝のシグナル」**として配信する。
本体（ニュース版）とは独立した第2のLINE通知。**本体のピックアップロジックには一切触れない。**

## 確定済みの設計判断（2026-06-23）

1. **検知軸 = 値上がり率＋出来高急増の複合**：「大幅高」かつ「出来高が普段より急増」の両方を満たす銘柄に絞る
   （単なる値上がりでなく、出来高を伴う本物の動意。薄商いの一過性を除外）。
2. **配信タイミング = 翌朝（前日の動意を寄り前に）**：前日大引けの動意を翌朝の寄り前に通知し、継続性
   （翻ろうそく/連続性）を狙う。本体ニュース版の「寄り前に絞る」思想・柱2破棄と整合（場中追走はしない）。

## データソース・部品（すべて既存の再利用）

- **動意の母集団**: `feedback/ranking.py` の値上がり率ランキング（`__PRELOADED_STATE__`/httpx取得・検証済）。
  中小型・非ETFフィルタ（`in_universe`）もそのまま流用。
- **出来高急増の算出**: `monitor/quotes.py` の日足系列（range=5d で close/volume 履歴が取れる）。
  当日出来高 ÷ 直近数営業日の平均出来高 = **出来高急増倍率**。
- **配信**: `monitor/notifier.py`（LINE multicast）と `store/recipients`（受信者）をそのまま使用。
- → 新規スクレイパ・新依存なし。

## 検知ロジック（v1）

1. 値上がり率ランキング上位N（既定30）を取得し、中小型・非ETFに絞る。
2. 各候補について quotes で日足を取り、**出来高急増倍率 = 当日出来高 / 直近4営業日の平均出来高** を算出。
3. フィルタ:
   - 値上がり率 >= `tech_min_change_pct`（既定 5.0%）
   - 出来高急増倍率 >= `tech_min_volume_surge`（既定 2.0倍）
4. **本体ニュース版で同じ朝に配信済みの銘柄は除外**（二重配信防止。digest_runs/signals と突き合わせ）。
5. 残りを値上がり率降順で「📊 テクニカル注目」LINEとして配信。0件なら「該当なし」を1通（無通知＝障害と区別、本体と同方針）。

## 配信フォーマット（案）

```
📊 6/24(火) 朝のテクニカル注目 3件
（前日の出来高急増＋大幅高。材料の有無は問わず）

📈 トーシンHD(9444)
　前日 +34.2% / 出来高 5.8倍
　https://finance.yahoo.co.jp/quote/9444.T

…
```

- ニュース版(✅/❌＋🔥)と**ヘッダ・アイコンで明確に区別**（📊／📈）。
- 終値・前日比%・出来高倍率を載せる（テクニカル版は値動き指標そのものが主役なので、ニュース版と違い
  前日比%・出来高を**あえて表示する**）。リンクはYahooの個別ページ。

## 設定（settings・既定値）

| キー | 既定 | 意味 |
|---|---|---|
| `tech_min_change_pct` | `5.0` | 値上がり率の下限(%) |
| `tech_min_volume_surge` | `2.0` | 出来高急増倍率の下限(倍) |
| `tech_top_n` | `30` | ランキング上位何件を母集団にするか |
| `tech_dedup_with_news` | `true` | 本体ニュース版で配信済みの銘柄を除外するか |

## テスト観点

- `FORCE_LOCAL_DB=1`／`with TestClient(app)`。
- ランキング→候補抽出→出来高急増算出→フィルタの各段を合成データで検証（quotes/ranking をモック）。
- 二重配信除外（news digest と同銘柄）の検証。
- 0件時の「該当なし」配信。LINE失敗時の挙動（notifier 既存の堅牢化に乗る）。
