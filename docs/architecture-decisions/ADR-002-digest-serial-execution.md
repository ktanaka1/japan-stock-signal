# ADR-002: digest を「収集→分析→配信」の直列実行にする

## 状況

朝のダイジェスト配信を平日7:30に行いたい。しかし GitHub Actions の cron は
**大幅な遅延・スキップが常態**（実測: 7:30設定が8:55発火、collectorは24時間で18回中4回しか発火しないことも）。

当初は collector / monitor / digest をそれぞれ独立した cron で動かしていたが、
「配信直前までに最新ニュースが収集・分析されている」保証がなかった。

## 選択肢

- **digest ジョブ内で収集→分析→配信を直列実行**する
- 各ジョブを独立cronのまま運用し、発火タイミングの偶然に任せる
- 外部cron（cron-job.org等）でActionsの遅延を回避する

## 決定

digest ワークフロー内で **collect → monitor → digest を1実行で直列**に走らせる（コミット 93b877f）。
収集・分析ステップは `continue-on-error: true` + タイムアウトを設定し、失敗しても配信は必ず実行する。

## 理由

- 発火が遅延しても、**LINE送信の直前に最新ニュースを取り込める**ため取りこぼしがない
- 収集・分析が失敗しても配信自体は走る（無通知＝障害、を避ける）
- 独立cronの定期実行（collector/monitor）は引き続き併用し、日中にシグナルを蓄積しておく

## 補足

- 実データ上、早朝のニュース量は少なく（夜22時台120件に対し朝は11件程度）、適時開示は15時の引け後に集中する
- ユーザーは配信が7:30〜9:00ごろにずれることを許容済み（寄付き9:00前に届けば良い）
